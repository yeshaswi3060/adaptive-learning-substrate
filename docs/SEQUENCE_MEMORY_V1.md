# Sequence memory V1 — prospective diagnostic, 2026-09-06

## Objective and hypothesis

Test the implemented non-attention sequence core on actual multi-token memory,
not just next-byte frequency learning. Separate architecture capacity from the
local eligibility/random-feedback approximation. This is an engineering-scale
diagnostic, not a Transformer replacement result or an official V3 readiness gate.
All settings below are fixed before the first metric. Report failures unchanged.

## Fixed architecture and conditions

Use the existing CpuSequence recurrence and initialization exactly: 32 gated
units, four fixed non-self recurrent parents per unit, 256 output bytes, 25,056
trainable parameters. Every condition starts from identical parameters/topology
for its seed. No attention, external memory bank, per-key parameter routing, or
hard-coded cue latch is added. State resets only between examples, except in the
explicit evaluation ablation. The candidate's local rule remains unchanged.

1. Local: existing plastic core plus readout, existing rates/clipping.
2. Readout: identical recurrence, frozen core, existing readout updates.
3. BPTT: same recurrence, exact finite-episode cross-entropy gradient including
   every cross-unit recurrent derivative. One Adam update per episode, rate
   0.003, betas 0.9/0.999, epsilon 1e-8, gradient global norm clipped at 1,
   weights clipped at +/-3. Fixed feedback is unused and never trained.

BPTT is a diagnostic reference, not a change to the eventual local-learning
objective. Its learning rule, optimizer, and update timing differ: local/readout
update after each answer token; BPTT holds weights constant within an episode
and averages answer-token loss before one update. Data and supervised target
budgets are matched; training FLOPs/optimizer steps are not. This experiment
does not establish an efficiency advantage or isolate feedback from optimizer
choice. BPTT failure would not prove that the architecture lacks capacity.

## Frozen data and evaluation matrix

Model seeds are 16000, 16001, 16002. Separate model instances train on each task;
this is not a demonstrated multitask/continual-learning model. RNG streams are
PCG64 keyed by SHA-256 of the version, seed, task, split, and delay.

| Task | Prompt | Answer |
|---|---|---|
| copy3 | COPY, 3 independent values, DISTRACTOR, random noise, QUERY | Original three values, in order |
| recall4 | RECALL, 4 randomly ordered unique key/value pairs, DISTRACTOR, random noise, QUERY, selected key | The corresponding value |

Values are bytes 64..71 (8 equally likely choices). Keys are 32..35. Distractors
are independent bytes 128..143. Markers are COPY=240, RECALL=241, DISTRACTOR=242,
QUERY=243. Copy sequences are not generated by an externally chained solution;
the recurrent model must produce all three answer tokens.

Each seed/task trains on 512 examples once, alternating delays 4 and 16.
Each model is evaluated on 128 independently generated held-out examples at
each delay 4, 16, 32, 64. Delays 32/64 are unseen in training. All train/test
prompts are checked for exact disjointness. All six datasets are written and
hashed before any model metric or training result is computed.

Supervise only answer tokens; context/noise tokens have no loss. Prediction
precedes target revelation. Training and NLL use teacher forcing after each
prediction, while primary accuracy uses fully free-running outputs with no
target-fed answer inputs. Report token accuracy, exact whole-answer accuracy,
and teacher-forced NLL separately. These are supervised memory tasks, not a
language-model corpus or a broad generalization claim.

## Controls and fixed diagnostic acceptance

For every condition evaluate normal recurrence and a reset immediately before
the final query input (QUERY for copy; selected key for recall). The reset
removes preceding memory without changing weights. Compare with a Laplace-1
bigram trained on precisely the same supervised token pairs. A symbolic parser
is a task-generator positive control only, never a model feature or competitor.
For orientation, independent uniform guesses over the eight valid values have
expected token accuracy 1/8 and copy-exact accuracy 1/512. Model predictions and
losses use all 256 output bytes, without an answer-alphabet mask.

The local candidate passes this diagnostic only if every seed, both tasks,
and every evaluation delay achieve token accuracy >=0.75 and normal-minus-reset
token accuracy >=0.15; copy-exact accuracy must also be >=0.50. No threshold,
seed, task count, or training budget is changed after valid results. Per-cell
results are mandatory; pooled means must not hide seed/delay failures. These
descriptive thresholds award zero official readiness points. No inferential
significance or validated confidence interval is asserted from this small run.

## Verification, resources, and interpretation

Before metrics, finite differences validate all eight parameter families across
multiple time steps, including recurrent cross-unit paths. The separate forward
implementation must exactly match original CpuSequence predictions. Test target
causality, no evaluation updates, constant topology/feedback, and checkpoint
compatibility. Unit tests use non-experiment seeds and never assigned V3 seeds.

Run sequentially on CPU with one BLAS thread, no torch, no GPU context, and no
worker pool. Check at least 128 MiB available host RAM before startup and every
32 training examples/evaluation cell. The small exact-gradient tape is bounded
to 256 tokens per episode; it is a training reference, not growing inference
memory. Record actual process working set/commit and per-condition elapsed time.
These CPU measurements do not constitute a GPU-throughput or Transformer cost
comparison. The older official V3 8 GiB resource gate remains unchanged.

Freeze source/protocol/test/configuration, executable/library version, and all
data hashes before metrics. Use new immutable output directories. Rehash sources
at model/publication boundaries. A complete second fresh-process training run
must reproduce all scientific rows/checkpoints exactly. A third process must
regenerate datasets and replay all normal/reset test predictions through the
original CpuSequence evaluator from saved checkpoints; probabilities must agree
within 1e-12 and free-running argmaxes must agree exactly. Reopen reports and
sidecars. Keep historical source/data/evidence unchanged.

If exact-gradient training succeeds where local learning fails, prioritize
local-credit and optimizer diagnosis without declaring the recurrence broken.
If both fail, prioritize capacity/training-budget diagnosis and a prospectively
registered follow-up. Competitive text prediction and matched Transformer/state-
space comparisons remain later required tests. Official readiness remains 21/100.
